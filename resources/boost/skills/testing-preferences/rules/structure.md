# Names, layout, and grouping

- Name tests by the behavior being proven.
- Keep names short, specific, and easy to scan when a behavior fails.
- Avoid implementation details in test names.
- Group tests to match the application structure unless a clearer domain boundary exists.
- Keep related tests together and order them by behavior path.
- Use one file for one shared concept; do not mix unrelated classes unless the file intentionally verifies that shared concept.
